API Estatus de Unidades

Consulta en tiempo casi real qué unidades de un centro operativo están detenidas o en ruta, con su ubicación y el tiempo que llevan detenidas.

GET https://telemetria.tdr.com.mx/telemetria/consultarEstatus?centro_operativo=EC-05

Acceso y API key

La API solo acepta conexiones por HTTPS. Cada sistema que la consume recibe su propia API key, que identifica a quien consulta.

1 · Recibe el enlaceTe enviaremos la API key mediante un Send de Bitwarden.
2 · Ábrelo una vezEl enlace expira y puede tener un número limitado de accesos. Ábrelo en cuanto lo recibas.
3 · GuárdalaCopia la key a tu gestor de secretos o variable de entorno del servidor que hará las consultas.
La API key es personal de tu sistema No la compartas, no la escribas en el código fuente ni en repositorios, y no la uses desde un navegador o una app móvil. Si el enlace expiró antes de abrirlo, o crees que la key se expuso, solicita una nueva: la anterior se revoca sin afectar a otros consumidores.

Dirección del servicio: https://telemetria.tdr.com.mx

Cómo consultar

Petición

ElementoValorDescripción
MétodoGETSolo lectura. No se aceptan otros métodos.
Ruta/telemetria/consultarEstatusTambién responde con diagonal final.
Parámetrocentro_operativoUno o varios centros operativos, o TODOS. Ver la tabla siguiente. Si se omite, se usa EC-05.
EncabezadoX-API-KeyTu API key. Obligatorio. Va en el encabezado, nunca en la URL.

Uno, varios o todos los centros

Valor de centro_operativoConsultaResponde
EC-05Un centroUn objeto
EC-05,EC-10Varios centros, separados por coma (máximo 10)Una lista, un objeto por centro
TODOSTodos los centros operativos activosUna lista, un objeto por centro

Centros disponibles hoy: EC-01, EC-02, EC-03, EC-04, EC-05, EC-06, EC-08 y EC-10. Si se da de alta un centro nuevo, queda disponible automáticamente; con TODOS lo recibirás sin cambiar tu integración.

Ejemplos

bash
curl -s "https://telemetria.tdr.com.mx/telemetria/consultarEstatus?centro_operativo=EC-05" \
  -H "X-API-Key: $TDR_TELEMETRIA_API_KEY"
PowerShell
$respuesta = Invoke-RestMethod `
  -Uri "https://telemetria.tdr.com.mx/telemetria/consultarEstatus?centro_operativo=EC-05" `
  -Headers @{ "X-API-Key" = $env:TDR_TELEMETRIA_API_KEY } `
  -TimeoutSec 30
$respuesta.unidades | Where-Object estatus -eq "DETENIDO"

Probar con Postman

La colección trae tres consultas listas: un centro, varios centros y todos los centros. La API key ya está configurada como encabezado X-API-Key para toda la colección.

Descargar colección de Postman

  1. En Postman, elige Import y arrastra el archivo descargado. Si la descarga no funciona, copia el JSON de abajo y pégalo en Import.
  2. Abre la colección API Estatus de Unidades - TDR, pestaña Variables, y escribe tu API key en apiKey. Guarda con Ctrl+S.
  3. Abre cualquiera de las consultas y presiona Send.
No compartas la colección con la key escrita Si exportas o compartes la colección, borra antes el valor de apiKey. En un workspace de equipo, guárdala como secreto o en un entorno privado.

Respuesta

Una consulta correcta responde 200. Con un solo centro, la respuesta es un objeto JSON como el del ejemplo. Con varios centros o TODOS, es una lista de esos objetos, uno por centro, cada uno con su propia fecha y hora. Las unidades vienen ordenadas con las detenidas primero.

Campos

CampoTipoDescripción

fecha, horatextoMomento en que se calculó el estatus, en hora del centro de México (AAAA-MM-DD, HH:MM:SS).
total_unidadesenteroNúmero de unidades en unidades.
resumenobjetoConteo de unidades por estatus: detenido y ruta.

unidades[].estatustextoDETENIDO o RUTA. Ver Qué significa cada estatus.
unidades[].tiempo_minutosentero o nullMinutos que lleva detenida. null en unidades en ruta, o si la unidad se acaba de detener y aún no hay suficiente historial para calcularlo.
unidades[].coordenadasobjeto o nulllatitud y longitud en grados decimales (WGS84). null si no hay posición.
unidades[].ubicaciontextoDirección aproximada de la última posición.
unidades[].fecha_gpstexto o nullHora en que el GPS reportó esa posición, en hora del centro de México (AAAA-MM-DD HH:MM:SS). Una unidad detenida con el motor apagado reporta con menos frecuencia, así que su fecha_gps puede ser anterior: la posición sigue siendo la última conocida.

Qué significa cada estatus

Cada unidad se valida con la telemetría GPS y con su historial de movimiento de las últimas horas. En los centros que cuentan con una segunda plataforma de telemetría, ambas lecturas se cruzan y, cuando no coinciden, prevalece la más reciente.

EstatusSignificadotiempo_minutos
DETENIDOLa unidad no se está moviendo. Incluye unidades que se acaban de detener.Minutos detenida, o null si se acaba de detener
RUTALa unidad está en movimiento, aunque sea a baja velocidad por tráfico.null

Unidades que no aparecen

La respuesta incluye solo unidades con viaje en curso. No aparecen:

  • Unidades dentro de una base, patio o instalación de cliente, o detenidas a menos de 400 m de una de ellas.
  • Unidades cuya posición GPS no se ha actualizado en más de 60 minutos.

Si una unidad que esperas no aparece, lo más probable es que esté en uno de estos casos.

Códigos de error

Los errores responden con un JSON de la forma {"detail": "mensaje"}.

CódigoCausaQué hacer
401Falta el encabezado X-API-Key o la key no es válida.Revisa que envíes la key completa en el encabezado. No reintentes en automático: cada intento fallido cuenta para el bloqueo.
403Tu IP superó el límite de peticiones por minuto o de conexiones simultáneas.Espera un minuto y reduce la frecuencia.
404Algún centro operativo no existe. El mensaje dice cuál.Revisa el valor de centro_operativo.
422Parámetro con formato inválido, o más de 10 centros en una consulta.Corrige la petición, o usa TODOS.
429Tu IP quedó bloqueada temporalmente por varios intentos con una key inválida.Espera el tiempo que indica el encabezado Retry-After (en segundos) y corrige la key.
502Las plataformas de telemetría no respondieron.Reintenta en 1 a 3 minutos.
503El servicio no está disponible temporalmente.Reintenta en unos minutos; si continúa, avísanos.

Buenas prácticas

  • Consulta desde tu servidor, nunca desde un navegador o app móvil: la key quedaría expuesta a cualquier usuario.
  • Guarda la key fuera del código, en una variable de entorno o un gestor de secretos.
  • Reintenta solo errores temporales (502, 503), con una espera creciente entre intentos (por ejemplo 1, 2 y 4 minutos). No reintentes 401, 404 ni 422.
  • Usa fecha y hora para mostrar a tus usuarios qué tan reciente es la información.
  • Identifica unidades por unidad como texto; no asumas que siempre será numérico.
  • Tolera campos nuevos: en versiones futuras podríamos agregar campos a la respuesta sin cambiar los existentes.
